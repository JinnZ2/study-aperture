# Assessor-reliability study report

## 1. Experiment identity and version

Experiment ID: `UNDECLARED`. Protocol/scoring version: `UNDECLARED`. Status: `NOT_EXECUTED`. Identify whether every reported result is constructed, model-produced or independently reviewed. Do not mix software fixtures into model-performance denominators.

## 2. Repository and frozen files

Repository commit: `UNDECLARED`. Freeze manifest SHA-256: `UNDECLARED`. Include the exact file inventory, experimental implementation hashes, case/source hashes and version. State deviations or unreconciled bindings beside the affected observations.

## 3. Model, prompt and environment

For each execution condition, identify model and exposed version, exact prompt/instruction hashes, assessment date, environment, tool/retrieval access, supplied versus retrieved evidence, prior-information uncertainty, errors, retries and truncation. Unknown identifiers remain unknown. Equivalent declarations are not independent attestations.

## 4. Case inventory and construction

List stable case/variant IDs, family, purpose, source package, introduced condition, construction method and limitations. Include declared perturbation dependencies: allowed/required changes, invariants, unresolved triggers, evidence justification and what cannot be established. Explain held-out status and accidental differences, if any.

## 5. Reference procedure

Keep source-grounded observations, independent reviewer assessments and adjudication in separate linked artifacts. Record reviewer identity/expertise, actual access, independence/blinding procedure and limitations. Describe how disagreement was preserved and identify unanswered reference questions. Do not call the resulting object ground truth.

## 6. Sample sizes and denominators

Report attempted executions, completed captures, invalid/unparsed/truncated/incomplete responses, eligible repeated pairs, eligible perturbation pairs, reviewer records, missing observations and unscorable records. Every count identifies its denominator and sampling unit. Repeated pairs are dependent and must not be presented as independent case samples.

## 7. Structural validation

Separate original transport/schema validity, required-field omissions, frozen deterministic invariant violations, incompleteness and mutation-history coverage. Cite individual run IDs and frozen validator evidence. Validity does not mean completion or interpretive correctness.

## 8. Results by dimension

Report evidence source selection, location, quotation fidelity, unsupported additions and omissions separately from qualification/conditional/scope fidelity, contradictions, uncertainty handling and provenance. For each measure give raw numerator, denominator, missing/unscorable/not-assessed counts and supported observations. Mechanical exact matches cannot stand in for semantic review.

## 9. Repeatability and perturbation

Report exact agreement by field, evidence-selection variation, uncertainty variation and prespecified material-disagreement flags. Distinguish changed conditions from equivalent repetitions. For each controlled variant, cite source changes, expected dependencies, actual changed/invariant fields, justified changes and remaining semantic questions. An unchanged output is not inherently a success.

## 10. Reviewer agreement and disagreement

Give field-level counts/denominators, prevalence, missing observations and disagreement categories. Preserve evidence-location, interpretation, scope, terminology and other disagreements. If a chance-corrected statistic or uncertainty interval is used, name it and justify its sampling/independence/class assumptions. Agreement does not establish truth or independence.

## 11. Failure examples with source context

For each failure, cite original source passage/location/version, raw output/run ID, mechanical or reviewer observation, primary/secondary category, transformation and justification. Keep the unchanged original observation. Proposed category extensions remain separate. Avoid claiming an unsupported proposition is globally false merely because its selected quote differs.

## 12. Unscorable and unresolved cases

List inadequate references, unavailable material, unknown exposure, unsupported semantic decisions and unresolved reviewer disagreement. Explain why each is unscorable or unresolved; neither equals pass or fail.

## 13. Deviations and stopping events

Record changed test construction, internal reference inconsistency, source/version mismatch, environment changes and scoring revisions. Preserve earlier attempts. Name correction/revision versions and whether older data were explicitly reanalyzed under a new separately labeled analysis.

## 14. Limitations and untested conditions

Declare small/dependent samples, public versus hidden cases, unverified model metadata, reviewer limits, source authenticity limits, controlled-retrieval coverage and tests not run. Do not infer training exposure or confidence calibration from stated numbers or prior knowledge.

## 15. Proposed changes separated from findings

Observed findings: link only to recorded evidence. Proposed future experiments or core changes: label `PROPOSED`, give intended use, consequential errors and evidential basis. No promotion is automatic; no core card/schema change follows merely from this report. A useful experiment may expose poor assessor performance and unresolved questions.
